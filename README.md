# Personal Follower

유튜브 시청 기록을 바탕으로 사용자의 관심사를 분석하고, 오늘 볼 만한 영상 주제를 추천하는 서비스입니다.

1차 버전(2024.07 ~ 2025.01, 교내 SW 공모전 우수상)은 시청 기록 수집과 카테고리 분류까지 구현했습니다.
2차 버전인 이 저장소에서는 Spring Boot 기반으로 구조를 다시 잡고, 공식 YouTube Data API와 벡터 검색 + LLM 추천을 붙였습니다.

<br>

## 프로젝트 개요

키워드가 일치하는 영상만 보여 주는 방식으로는 사용자가 실제로 어떤 주제에 관심이 있는지 알기 어렵습니다.
그래서 사용자가 본 영상의 제목·태그·설명에서 명사를 뽑아 관심사를 수치로 쌓고,
그 관심사와 비슷한 키워드를 벡터 검색으로 찾은 뒤 GPT에게 새로운 주제를 추천받도록 만들었습니다.

- 기간: 2025.06 ~ 2025.07 (2차 재설계)
- 인원: 개인 프로젝트
- 기술 스택: Java 17, Spring Boot 3.5, Spring Security(OAuth2), Spring Data JPA, Spring Data MongoDB, Spring AI, MySQL, MongoDB, Qdrant, OpenAI(gpt-3.5-turbo), Open Korean Text

<br>

## 전체 흐름

```
[Google 로그인]
      ↓
[크롬 방문 기록 수집]  Chrome History(SQLite) → 유튜브 영상 URL만 추출
      ↓
[영상 정보 조회]       YouTube Data API (로그인한 사용자의 OAuth 토큰 사용)
      ↓
[관심사 분석]          제목·태그·설명 → 명사 추출 → 사용자별 명사 빈도 누적 (MongoDB)
      ↓
[추천]                 상위 관심 명사 → Qdrant 유사 키워드 검색 → GPT 추천 → 결과 다시 저장
```

<br>

## 주요 구현 내용

### 1. 크롬 방문 기록에서 유튜브 시청 기록 수집
- 크롬은 실행 중에 방문 기록 DB(SQLite)를 잠그고 있어서, 파일을 복사한 뒤 복사본을 읽도록 했습니다.
- 크롬은 시간을 1601년 기준 마이크로초로 저장합니다. 이를 일반 시간으로 바꾸는 변환을 직접 구현했습니다.
- 매번 전체 기록을 읽지 않도록, MongoDB에 저장된 **마지막 시청 시간 이후의 기록만** 가져옵니다. 처음 수집할 때는 최근 7일을 기준으로 합니다.
- `watch?v=`, `youtu.be/` 형태의 주소에서 영상 ID만 뽑아 냅니다.

### 2. yt-dlp에서 YouTube Data API로 전환
- 처음에는 yt-dlp를 외부 프로세스로 실행해 영상 정보를 가져왔습니다. 하지만 영상마다 프로세스를 띄워야 해서 느리고, 브라우저 쿠키에 의존하는 문제가 있었습니다.
- Google OAuth 로그인을 붙이고, 로그인한 사용자의 Access Token으로 **공식 YouTube Data API**를 호출하도록 바꿨습니다.
- 기존 yt-dlp 방식은 별도 서비스(`HistoryYtDlpService`)로 분리해 두어, 두 방식을 비교할 수 있게 남겼습니다.

### 3. 한국어 명사 추출로 관심사 수치화
- Open Korean Text로 제목·태그·설명을 정규화·토큰화하고, 일반 명사와 고유 명사만 남깁니다.
- 조사뿐 아니라 "충격", "클릭", "필수", "당장"처럼 **유튜브 제목에 자주 붙는 홍보성 표현**을 불용어로 따로 정리해 관심사 분석에서 뺐습니다.
- 사용자별로 명사 등장 횟수를 누적해(`user_noun_stats`) 상위 N개를 관심사로 사용합니다.
- 같은 영상을 다시 본 경우에는 새로 저장하지 않고, 시청 시간과 추출 결과만 갱신합니다.

### 4. 벡터 검색 + GPT 기반 주제 추천
- 관심 명사마다 Qdrant에서 의미가 비슷한 키워드를 찾고, 원래 관심사와 함께 GPT에게 전달해 오늘 볼 만한 주제 3개를 받습니다.
- 응답은 JSON 배열 형식으로만 받도록 프롬프트를 고정해, 파싱이 실패하지 않게 했습니다.
- GPT가 추천한 키워드는 다시 Qdrant에 저장합니다. 추천을 할수록 비슷한 키워드 후보가 쌓여, 다음 검색이 점점 풍부해집니다.

### 5. 목적에 따라 저장소 분리
| 저장소 | 저장 데이터 | 이유 |
|---|---|---|
| MySQL | 회원 정보 | 이메일 유일성 등 정해진 구조의 데이터 |
| MongoDB | 영상 정보, 사용자별 명사 통계, 추천 기록, 카테고리 연관 통계 | 태그·명사 목록처럼 길이가 정해지지 않은 데이터 |
| Qdrant | 키워드 벡터 | 의미 기반 유사 키워드 검색 |

- 추천 기록(`user_recommend_logs`)에는 입력 관심사, 추천 결과, 사용 모델을 함께 남겨 나중에 결과를 비교할 수 있게 했습니다.
- 관심사별로 어떤 키워드가 함께 추천됐는지 횟수를 모아(`global_category_links`) 전체 사용자 기준의 연관 데이터도 쌓습니다.

## API

| Method | URL | 설명 |
|---|---|---|
| GET | `/api/history/extract/ytapi` | 크롬 방문 기록 수집 → YouTube Data API로 영상 정보 저장 |
| GET | `/api/history/extract/ytdlp` | 같은 작업을 yt-dlp 방식으로 실행 (비교용) |
| GET | `/api/recommend` | 로그인한 사용자의 관심사 기반 추천 키워드 조회 |

모든 요청은 Google 로그인 후 사용할 수 있습니다.

<br>

## 실행 방법

1. MySQL, MongoDB, Qdrant를 실행합니다.
2. `src/main/resources/application.yml`에 아래 값을 설정합니다. (저장소에는 포함하지 않았습니다)
   - MySQL 접속 정보
   - MongoDB 접속 정보
   - Qdrant 접속 정보
   - Google OAuth Client ID / Secret (YouTube Data API 읽기 권한 포함)
   - `openai.api.key`
3. 애플리케이션을 실행합니다.
   ```bash
   ./gradlew bootRun
   ```
